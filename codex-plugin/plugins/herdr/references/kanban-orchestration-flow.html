Herdr Kanban Automation Flow

Plugin-side orchestration only. Herdr core already provides the control plane: create workspaces, run commands in panes, wait on status, read output, and close panes.

Spawned Codex runs YOLO

Inputs

Herdr Kanban Board

Cards are the only handoff surface: title, description, status, attached pane, and visible agent state.

  • todo ready work
  • ongoing claimed work
  • reviewing validated work
  • blocked human/manual input
  • done accepted work
poll or subscribe

Herdr Control Plane

The coordinator uses existing CLI/socket commands as its automation surface.

  • workspace create|close
  • tab create|close
  • pane run|read|close
  • agent wait|send

Ticks

Periodic coordinator and sweeper ticks make the loop recoverable when no event stream is available.

Plugin Runner

herdr-kanban-run

Long-running shell script that composes one-shot scripts. It keeps no private source of truth.

while true; do sweep; review; dispatch; sleep "$interval"; done
Sweep Repair stale cards, dead panes, missing evidence, and broken ownership.
Review Route Assign reviewing cards before starting more implementation work.
Dispatch Assign ready todo cards to idle worker panes.
Human Gate Surface UI review, release, publish, delete, and credential work.

Provision Role Panes

The runner creates a workspace or tab per card, then runs Codex in the root pane Herdr just created. No extra side split is created.

herdr pane run <root-pane> "codex --dangerously-bypass-approvals-and-sandbox --cd <worktree> '<role prompt>'"

Role Lifecycle

The runner starts the pane, sends or embeds the card prompt, waits for agent state, reads output when needed, and closes disposable panes after board state is stable.

Outcomes

Worker Agent

Uses herdr-kanban-worker, attaches the pane, implements scoped work, records validation evidence, commits and pushes a task branch, then moves the card forward.

todo -> ongoing -> branch pushed -> reviewing

Reviewer Agent

Uses herdr-kanban-reviewer, checks the pushed branch, acceptance, and validation evidence, then merges accepted work or returns the card.

reviewing -> merge -> done | todo | blocked

Human Review

Cards that require judgment or irreversible action stop here with explicit metadata and instructions.

  • review_state: human-review-required
  • blocked_reason: concrete next action

Recoverable Restart

If the runner exits, restart reads the board and live Herdr panes, sweeps invariants, closes dead disposable panes, and continues from card state.

Session Policy

Default to disposable spawned Codex panes for routine work. Persistent or manual sessions are optional capacity, not the core automation path.

Default Safety

YOLO applies only inside spawned Codex panes. Workers may push task branches for review; reviewers own merges and integration pushes when repo rules allow them.

Plugin Boundary

No Rust core changes. Scripts use Herdr CLI/socket APIs and store coordinator decisions back into card descriptions.
